0. WHAT THIS EXPERIMENT IS AND IS NOT
-------------------------------------
User-directed reboot WITHOUT prerequisites (addendum): Termux:Boot was
never installed; the transport was ABSENT at reboot time. Mechanically
tested: the boot-time supervision chain (boot glue + termux-services)
and the conservatism of the watchdog while blind. NOT tested:

- H3 / REBOOT_AUTONOMOUS_RECOVERY = NOT_TESTED. No dead post-reboot
  server was recovered: the server was already UP (PID 6754) when the
  transport returned. 27 conservative skips, then UP. No recovery was
  delegated — none was needed, none occurred.
- The server did NOT literally survive as a process: pre-reboot PID
  2593 (itself recovered from an earlier DOWN that same evening;
  8679 was dead before that) -> post-reboot PID 6754. Correct
  phrasing: "Shizuku was functional post-reboot without the watchdog
  having to perform a server recovery during this experiment."
- The transport was restored MANUALLY via LADB by the operator:
  MANUAL_INTERVENTION (transport only), NOT autonomous recovery.

Per the addendum: no token flips beyond the scope explicitly recorded
here. REBOOT_PERSISTENCE = VERIFIED is claimed ONLY under the scoped
meaning below; the preregistered app-driven H2 was inoperative and H3
was not exercised at all.

Mechanically demonstrated (the five claims of the scoped verdict):
1. Termux:Boot-plugin infrastructure executed the bootstrap from
   ~/.termux/boot/ at device boot (evidence log 22:36:20, before any
   interactive session).
2. runsvdir + runsv + watchdog started from boot, unattended (PIDs

   consecutive skips, zero false recoveries while blind.

5. verify.sh confirmed full functionality post-reboot (UP +
   FUNCTIONAL, rish OK).

Explicitly NOT demonstrated:
- Autonomous recovery of a dead server post-reboot (H3) — the core
  scenario of the original preregistration. A valid future attempt
  requires, per the preregistration: transport alive BEFORE reboot,
  com.termux.boot installed + whitelisted, and the server DOWN when
  the transport returns.
- Termux:Boot-app-driven supervision (preregistered H2 variant).
- Process survival of the server across reboot — disproven in the
  expected direction (6754 != 2593 != 8679), consistent with H1.
- Who launched the post-reboot server instance (no evidence; unknown).
